## AgentSociety 平台代码导览（中文 + 英文关键词）

本文面向开发者，按目录/文件粒度说明 `@agentsociety/agentsociety` 的核心模块、关键职责与相互关系，并在文中保留常用英文关键词（如 Agent / Memory / Environment / LLM 等），方便跨语言检索。

### 一、整体概览（Overview）

- 核心目标：在城市级模拟环境（Environment）中，创建具备记忆（Memory）、感知、交流（Message）与决策（LLM+Blocks）的多类 Agent，并以可配置的工作流（Workflow）推进仿真。
- 平台关键构件：
  - Simulation Engine（`simulation/`）：驱动仿真生命周期与工作流执行。
  - Agent Framework（`agent/`）：Agent 抽象、Blocks、调度与消息能力。
  - Memory System（`memory/`）：状态（KVMemory）与事件流（StreamMemory）+ VectorStore 检索。
  - Environment（`environment/`）：城市仿真服务、经济子系统、地图与时空管理。
  - LLM Client（`llm/`）：多提供商并发调用与 Token 统计。
  - Messaging（`message/`）：消息收发与 Supervisor 拦截（MessageInterceptor）。
  - Storage（`storage/`）：实验信息、对话、调查、状态、任务结果等持久化。
  - Configs（`configs/`）：仿真与个体求解配置、AgentConfig/Workflow 等。
  - Web API（`webapi/`）：FastAPI 管理服务与可视化对接。

典型链路：
```
Config -> AgentSociety.create(...) -> SimulationEngine/IndividualEngine
  -> init(): LLM / Environment / Messager / Embedding / Agents / DB
  -> run(): Step/Run/Survey/Message/Intervene/Save/Metric
```

### 二、运行时流程（Runtime Flow）

1) 读取 `configs/`（LLM/Env/Map/Agents/Workflow）。
2) `AgentSociety.create` 选择 `SimulationEngine`（多代理仿真）或 `IndividualEngine`（任务求解）。
3) 初始化阶段：
   - LLM（并发、轮询、统计）
   - EnvironmentStarter（启动或连接城市模拟器、Syncer、经济客户端）
   - Messager（轮次消息队列）、可选 MessageInterceptor（Supervisor 校验/说服）
   - Embedding（SparseTextEmbedding）
   - 根据 AgentConfig + MemoryConfigGenerator 生成 Agent + Memory（KV/Stream + VectorStore）
   - 数据库（DatabaseWriter）记录实验信息（ExpInfo）
4) 运行阶段：
   - `step()`：调度消息 -> Agent.run() -> 汇总日志/指标 -> 保存状态/上下文 -> 推送/拦截消息 -> 处理用户对话/调查 -> 推进环境 tick。
   - `run()`：按 WorkflowStep（STEP / RUN / INTERVIEW / SURVEY / INTERVENE / UPDATE_STATE / NEXT_ROUND / DELETE_AGENT / SAVE_CONTEXT / FUNCTION）执行。

### 三、目录与文件说明（Modules & Files）

#### simulation/
- `agentsociety.py`
  - 工厂（Factory）入口：`AgentSociety.create(config)` 返回 `SimulationEngine` 或 `IndividualEngine`。
  - 兼容旧构造器，委托底层引擎实例。

- `simulationengine.py`
  - 多 Agent 仿真主引擎。
  - 关键点：
    - 初始化 LLM / EnvironmentStarter / Messager / MessageInterceptor / Embedding / DatabaseWriter。
    - 基于 `AgentConfig` 和 `MemoryConfigGenerator` 构建各类 Agent（Citizen/Firm/Bank/NBS/Government/Supervisor）。
    - Supervisor 绑定到 `MessageInterceptor`，用于消息合法性校验与干预（persuasion）。
    - `gather/filter/update/send_survey/send_interview_message/send_intervention_message` 等高层 API。
    - `step/run/run_one_day` 执行流程；保存 `StorageStatus`、`StorageGlobalPrompt`、`StorageProfile` 等。

- `individualengine.py`
  - 个体任务求解引擎（Task Solver）。
  - 并发初始化 N 个 `IndividualAgentBase`，通过 `TaskLoader` 分发任务，收集结果（`StorageTaskResult`）。

- `type.py`
  - 枚举与日志聚合类型（ExperimentStatus, Logs）。

#### agent/
- `agent_base.py`
  - 基类 `Agent`：统一生命周期（init/reset/forward hooks/run/status_summary/close）、消息（to agent/AOI）、`BlockDispatcher`、`GatherQuery`。
  - 提供 `toolbox`（LLM/Environment/Messager/Embedding/DB）与 `memory`（Status/Stream）。

- `agent.py`
  - 具体基类：
    - `CitizenAgentBase`：绑定城市模拟与经济系统；支持调查（Survey）与访谈（Interview）存储。
    - `InstitutionAgentBase` 及派生（Firm/Bank/NBS/Government）：绑定经济系统。
    - `SupervisorBase`：必须实现 `forward(messages)`，与 MessageInterceptor 配合。
    - `IndividualAgentBase`：任务求解型 `run(task)`。

- `block.py`
  - `Block`：行为单元（类似 NN Layer）。
  - 含 `ParamsType/Context/OutputType`、可选 `block_memory`（独立 KVMemory）。
  - 钩子 `before_forward/after_forward` 与抽象 `forward(agent_context)`。

- `dispatcher.py`
  - `BlockDispatcher`：通过 LLM function calling 在已注册 Blocks 中选择最合适的 Block 处理当前意图（intention）。

- `prompt.py`
  - `FormatPrompt`：模板渲染，支持 `${status.*}`、`${profile.*}`、`${context.*}` 安全访问；输出 Chat 对话格式。

- `memory_config_generator.py`
  - 统一 `MemoryConfig/MemoryAttribute` 模型；默认 Citizen/Supervisor 属性；
  - 从文件（JSON/JSONL/S3）或分布（Distribution）生成/合并配置；注入 home/work AOI。

- 其他：`context.py`（DotDict/Context 装饰与合并）、`distribution.py`（随机分布）、`decorator.py`（方法注册/参数文档）、`toolbox.py`（AgentToolbox 与自定义 Tool）。

#### memory/
- `memory.py`
  - `KVMemory`：字段级存储与 Embedding 管理（add/update/delete），`similarity_search` 检索。
  - `StreamMemory`：时间序列事件（topic/day/time/location/cognition link），可过滤检索并格式化输出。
  - `Memory`：聚合 `status`（KV）与 `stream`，并统一初始化 embeddings。

- `const.py`
  - 结构类型（如 `SocialRelation`）供 Memory Config 使用。

#### environment/
- `environment.py`
  - `EnvironmentConfig` 与核心 `Environment`：
    - 地图（MapData/Proj）、城市模拟客户端（CityClient/person_service）、经济客户端（EconomyClient）。
    - 时间管理（tick -> day/time）、AOI 消息注册/撤销、POI 查询、人物增删改位、指标（metrics）采集。
  - `EnvironmentStarter`：下载/启动模拟器进程、初始化 Syncer、连接 server、推进 step。

- 其他文件：`mapdata.py`、`sim/*`、`economy/econ_client.py`、`syncer/*`、`utils/*`（端口、protobuf、base64、geo 等）。

#### llm/
- `llm.py`
  - `LLMConfig`（provider/base_url/api_key/model/concurrency/timeout）。
  - `LLM`：多配置轮询并发；Ray Actor（`LLMActor`）执行请求；工具调用（tools/tool_choice）；重试、超时、Token 统计、日志。

#### message/
- `messager.py`
  - `MessageKind`（agent-chat/user-chat/aoi-register/aoi-cancel）、`Message` 模型、`Messager` 收发/缓冲。

- `message_interceptor.py`
  - `MessageInterceptor`：持有 LLM 与 `Supervisor`，对一轮消息进行校验/过滤，并可注入说服消息（persuasion）。

#### storage/
- `type.py`
  - 持久化数据模型：`StorageExpInfo`、`StorageDialog`（Thought/Talk/User）、`StorageSurvey`、`StorageGlobalPrompt`、`StorageProfile`、`StorageStatus`、`StoragePendingDialog/Survey`、`StorageTaskResult`。

- 其余：`_base.py`、`database.py`、`model.py` 实现 `DatabaseWriter`，用于写入/读取消息、调查、状态、指标、任务结果与实验信息。

#### configs/
- `__init__.py`
  - `Config`（仿真）与 `IndividualConfig`（任务求解）；含 `EnvConfig`、`MapConfig`、`LLMConfig`、`AgentsConfig`、`ExpConfig`、`WorkflowStepConfig/WorkflowType`、`AgentFilterConfig`、`TaskLoaderConfig` 等聚合。

- `agent.py` / `env.py` / `exp.py` / `utils.py`
  - `AgentConfig`（agent_class/blocks/tools/memory_config_func/memory_from_file/memory_distributions 等校验与序列化）。
  - `EnvironmentConfig`、`ExpConfig`（workflow DSL）、加载工具（`load_config_from_file`）。

#### webapi/
- `app.py` 与 `api/*`、`models/*`
  - FastAPI 后端：启动/管理仿真、导出数据、WebUI 对接（实验、配置、Agent 模板、调查等）。

#### 其他重要目录
- `vectorstore/`：`VectorStore` 接口，`add_documents/similarity_search/delete_documents`，内被 Memory 使用。
- `cityagent/`：默认城市 Agent 与 Blocks 实现（经济/出行/认知/需求/社交等）。
- `survey/`：`models` 与 `manager` 封装调查流程。
- `taskloader/`：`TaskLoader` 与 `Task`，文件驱动的批量任务分发与结果收集。
- `filesystem/` 与 `s3/`：文件/对象存储后端客户端。
- `executor/`：进程/集群执行（如 kubernetes 适配在 `commercial/`）。
- `cli/cli.py`：命令行入口。
- `logger/`：统一日志入口（`get_logger()` 等）。

### 四、模块关系（Relations）

```
Configs -> AgentSociety.create -> Engine (Simulation/Individual)
  Engine.init:
    - LLM(LLMConfig[])  -> 并发调用、工具调用、日志/Token
    - EnvironmentStarter -> Map/Sim/Economy/Syncer/Tick/POI/AOI-message
    - Messager           -> 消息缓冲 + 分发
    - MessageInterceptor -> 需 Supervisor(Agent) 实现 forward
    - Embedding          -> fastembed SparseTextEmbedding
    - DatabaseWriter     -> Storage*（Exp/Status/Profile/Dialog/Survey/...）
    - MemoryConfigGenerator -> MemoryConfig/MemoryAttribute(默认+文件+分布)
    - Agent(AgentToolbox+Memory) -> BlockDispatcher/Blocks/Prompt

Engine.run/step:
  - fetch messages -> supervisor forward -> dispatch -> agents forward
  - gather/filter/update/send_* -> save status/context -> metrics -> next tick
```

### 五、典型扩展点（Extension Points）

- 新增 Agent：继承 `CitizenAgentBase`/`InstitutionAgentBase`/`IndividualAgentBase`；提供 `StatusAttributes`、`forward()`、可选 Blocks。
- 新增 Block：继承 `Block`，定义 `ParamsType/Context/OutputType/forward()`；注册到 `AgentConfig.blocks`。
- 自定义记忆结构：在 `MemoryConfigGenerator` 的 `class_config` 中追加 `MemoryAttribute`；或引入 `memory_from_file`。
- 自定义工作流：在 `ExpConfig.workflow` 添加 `WorkflowStep`（STEP/RUN/SURVEY/...）。
- 接入新 LLM：扩展 `LLMProviderType` 与兼容 `base_url`，或按现有 provider 配置。

### 六、英文关键词对照（Glossary）

- **Agent**：智能体（Citizen/Institution/Supervisor/Individual）
- **Block**：行为模块（可组合、由 Dispatcher 选择）
- **Memory**：记忆（`KVMemory` + `StreamMemory`）
- **VectorStore / Embedding**：向量检索与稀疏嵌入
- **Environment**：环境（Map/City/Economy/Syncer/Time/POI/AOI）
- **LLM**：大语言模型客户端（并发/重试/工具调用）
- **Messager / MessageInterceptor / Supervisor**：消息系统 / 拦截校验 / 监督者代理
- **Config / Workflow**：配置与工作流 DSL
- **DatabaseWriter / Storage***：数据库写入与持久化模型
- **TaskLoader**：任务装载与派发（个体求解）

如需更细粒度（例如 `cityagent/blocks` 各 Block 的输入/输出与 Prompt 模板），可继续在对应目录添加子章节。
